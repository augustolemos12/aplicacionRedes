SECTION 1 // TRANSPORTE TCP VS. APLICACIÓN HTTP/1.1

MODULE: socket_server.py

Capa de Transporte — TCP (Transmission Control Protocol): Opera sobre sockets de flujo (socket.AF_INET, socket.SOCK_STREAM). Garantiza entrega ordenada y libre de errores de un flujo continuo de bytes entre procesos, pero carece de delimitadores de mensaje: una invocación a sock.recv(4096) puede retornar desde un único byte hasta múltiples líneas agrupadas.

Capa de Aplicación — HTTP/1.1 (Hypertext Transfer Protocol): Implementada en server/http_parser.py y server/response.py. Impone una gramática determinista sobre el flujo TCP:

  • Línea de petición delimitada por CRLF (\r\n): MÉTODO RUTA VERSIÓN.
  • Colección de encabezados normalizados sin distinción de mayúsculas/minúsculas.
  • Secuencia centinela \r\n\r\n que separa los metadatos del cuerpo de entidad.
  • Lectura exacta de bytes del cuerpo gobernada por el encabezado Content-Length.

SECTION 2 // PARÁMETROS DEL SUBCONJUNTO IMPLEMENTADO

SPEC: RFC 9112 SUBSET
SUBSISTEMA ESPECIFICACIÓN OPERATIVA
CICLO DE CONEXIÓN Una transacción HTTP por socket TCP con cierre explícito (Connection: close). Sin keep-alive.
CONCURRENCIA Despacho multihilo (threading.Thread) con temporizador de lectura (socket_timeout).
MÉTODOS ADMITIDOS GET, HEAD y POST. Cualquier otro método recibe 405 Method Not Allowed + cabecera Allow.
CODIFICACIÓN DE TRANSFERENCIA Content-Length obligatorio para cuerpos. Transfer-Encoding: chunked se rechaza con 501 Not Implemented.
AISLAMIENTO DE SISTEMA DE ARCHIVOS Normalización de URL, rechazo de .. y verificación canónica con Path.resolve().is_relative_to(DocumentRoot).
CONTROL DE ACCESO HTTP Basic Auth validado contra hashes PBKDF2-HMAC-SHA256 (200.000 iteraciones) mediante hmac.compare_digest.
